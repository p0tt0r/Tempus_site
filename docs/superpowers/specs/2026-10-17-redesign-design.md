# Редизайн сайта УМЦ «Темпус» — описание дизайна

Дата: 2026-10-17. Статус: черновик на согласование.

## Зачем

Сайт ЧОУ ДПО УМЦ «Темпус» (umc-tempus.ru) нужен прежде всего для проверок Рособрнадзора: обязательный раздел «Сведения об образовательной организации» должен быть полным, доступным и работать без ошибок. Посетителей немного: в основном студенты, которые ищут программу обучения, и преподаватели, которым нужно расписание и иногда документы (контент преподаватели добавляют через админку Strapi). Вторая цель — сайт должен выглядеть как солидная образовательная организация, а не шаблон: сейчас это сине-фиолетовые градиенты, системный шрифт, разношёрстные стили.

Ориентиры, которые нравятся заказчику: hse.ru (сдержанность: белый фон, один синий, крупный текст, реальные фото) и donstu.ru (программы и плитки задач — «Расписание», «Обучающимся» — прямо на главной; шрифт Golos).

## Цели

1. Студент с главной за один шаг видит программы обучения и их ключевые факты (часы, срок, форма, документ об окончании) и переходит к полному описанию.
2. Преподаватель и студент с главной за один клик попадают в «Расписание» и «Документы».
3. Раздел «Сведения» — по-прежнему полный, структура и адреса неизменны, все ссылки работают; выглядит аккуратно и читается на телефоне.
4. Версия для слабовидящих.
5. Единая визуальная система на всех страницах: один шрифт, белый фон, один синий из логотипа, мотив «ступеней» из логотипа.

## Не цели

- Новые разделы, страницы, адреса, изменения меню по составу. Структура сайта согласована с требованиями к образовательной организации и не меняется.
- Любые изменения Strapi: типы контента, поля, данные, `cms/`, `.env`, конфиги сервера, Nginx.
- Изменение запросов к API (URL, `populate`, фильтры, сортировки, имена полей). Можно только по-другому показывать то, что уже приходит.
- Аналитика, cookies-баннер, формы с отправкой данных (персональные данные сайт не собирает — так и остаётся).
- Тяжёлая анимация и интерактив: посетителей мало, важны ясность и скорость.

## Анти-цели (провал, даже если «работает»)

- Сломанный или спрятанный раздел «Сведения», изменённые адреса `/sveden/...`.
- Шрифт или иной ресурс с несвободной лицензией (HSE Sans, Proxima Nova и т.п. — нельзя).
- Ресурсы, подгружаемые с чужих серверов (Google Fonts CDN и т.п.): IP посетителей не должен уходить третьим лицам.
- Абсолютные адреса API или порт 1337 в коде.

## Ограничения (из задания и сессии)

- Только фронтенд: `src/`, `public/`, `index.html`. React 19 + Vite + TypeScript, существующий стек.
- Без CSS-фреймворков и тяжёлых UI-библиотек. Шрифт — допустимая лёгкая зависимость или файлы в `public/fonts`.
- Запросы только по относительным путям `/api/...`, `/uploads/...`.
- Телефон директора в подвале — +7 (919) 870-67-27 — оставить; он намеренно отличается от номеров на странице «Контакты».
- Работа идёт так: основная сессия планирует и проверяет, код пишет субагент `coder` (Sonnet), по одному шагу плана на коммит с сообщением на русском.

## Принятые решения

### Шрифт

Golos Text (Александра Королькова, Виталий Кузьмин), лицензия SIL Open Font License 1.1 — проверено по `google/fonts/ofl/golostext/OFL.txt`. Кириллица есть. Файлы шрифта (woff2, начертания 400/500/600/700 или вариативный) хранятся в проекте, рядом лежит `OFL.txt`. Подключение через `@font-face` с `font-display: swap`. С Google не подгружать. Второй шрифт не нужен.

### Цвет

Из логотипа. Один фон, одни чернила, один акцент:

| Роль | Значение | Где |
|---|---|---|
| ground | `#ffffff` | фон страниц |
| ink | `#0b1f4d` | основной текст, заголовки, тёмные плитки |
| accent | `#0a52e0` | основная кнопка, ссылки, активный пункт меню |
| tint | `#eef3fb` | светлые поверхности: полоса меню, блок программы, боковое меню «Сведений» |
| muted | `#4a5875` | второстепенный текст (подписи, даты) |
| ступени | `#2f6df0`, `#1d5fe8`, `#0a52e0`, `#123c9e`, `#0b1f4d` | только мотив «ступеней» и тёмные плитки (`#0b1f4d`, `#13306e`, `#1b3f8c`) |

Без градиентов, без теней у элементов в покое (тень допустима только у того, что всплывает: выпадающее меню), без тонких рамок-разделителей — поверхности разделяются тоном (`tint`) и отступами. Основной текст — полными чернилами, не серым.

### Типографика

Мало размеров, большой разрыв между ними: заголовок первого экрана ~64px на компьютере / ~34–36px на телефоне; заголовки разделов ~34px / ~26px; текст 17–19px, межстрочный 1.5; подписи 14–15px. Заголовки: жирность 700, трекинг −0.02…−0.03em. Любой заголовок — не больше двух строк на любой ширине (подбирать размер на телефоне). Сентенциальный регистр, никаких капслоков с разрядкой и надписей-«eyebrow» над заголовками. Выравнивание по левому краю.

### Форма

Углы прямые (кнопки, плитки, картинки) — решено один раз для всего сайта. Кнопка — заливка `accent`, белый текст. Вторичное действие — текстовая ссылка цвета `accent` со стрелкой «→».

### Мотив «ступеней»

Из логотипа (лесенка горизонтальных полос со стрелкой вверх). Используется дозированно: лесенка из 5 полос растущей длины поверх нижнего края фото на первом экране главной; повторяется как тонкий узнаваемый элемент там, где уместно (например, у заголовка страницы или в подвале) — где именно, решает исполнитель, но не больше одного раза на экран.

### Шапка (все страницы)

Две строки на компьютере (>980px): сверху логотип + «УМЦ «Темпус»» слева, справа «Поиск по сайту» и «Версия для слабовидящих»; ниже — полоса `tint` во всю ширину с меню в одну строку, пункты распределены равномерно, без переносов, активный пункт подчёркнут `accent`. Пункты меню и их адреса — ровно как сейчас (включая выпадающее меню «Сведений» с 14 разделами и полное название «Сведения об образовательной организации»). На ≤980px — одна строка: логотип и кнопка «Меню»; выезжающее меню как сейчас (Escape, блокировка прокрутки, `inert`, ARIA — уже сделано, сохранить). «Версия для слабовидящих» на телефоне — внутри выезжающего меню.

### Главная

Порядок блоков (согласован на макете):

1. **Первый экран.** Слева: заголовок «Новая профессия — ступень за ступенью», под ним одна фраза («ЧОУ ДПО УМЦ «Темпус», Ростов-на-Дону. Профессиональная переподготовка с дипломом для тех, у кого есть или будет высшее образование.»), кнопка «Программы обучения» и ссылка «Сведения об организации →». Справа: фотография занятия (снимок из новости «Приветствуем вас на сайте…», файл `IMG_5638`), поверх её нижнего края — лесенка «ступеней». На телефоне фото сверху, текст ниже, кнопка во всю ширину. Фото — копия в статике проекта (не ссылка на `/uploads`, чтобы удаление новости в Strapi не ломало главную), оптимизированное (webp/jpg, разумный размер).
2. **Программы.** Светлый блок `tint`. Для каждой программы: строка «Программа профессиональной переподготовки», название крупно, 1–2 предложения описания, ссылка «Описание и рабочая программа →»; справа сетка 2×2 крупных фактов: «540 часов — объём программы», «1 год — продолжительность», «Очно-заочно — форма обучения», «Диплом — о переподготовке». Несколько программ — блоки друг под другом (или чередуются по тону), каждый со своими фактами.
3. **Плитки задач.** Три тёмные плитки во всю ширину: «Расписание — занятия и экзамены» → `/schedule`, «Документы — устав, лицензия, положения» → `/sveden/dokumenty`, «Сведения об организации — 14 обязательных разделов» → `/sveden`. На телефоне — друг под другом.
4. **Новости.** Три последние, как сейчас приходят из API: фото 3:2, дата, заголовок; ссылка «Все новости →».
5. Блоки «О центре», «Популярные разделы», «Поиск по сайту» с текущей главной — убрать или влить: «О центре» — в первую фразу/описание; «Популярные разделы» дублируют плитки и меню; поиск — в шапке. (Решение основной сессии; заказчик видел макет без этих блоков и согласовал.)

Ссылка «Программы обучения» ведёт на `/sveden/obrazovanie` (там программы и живут — структуру не меняем).

### Откуда берутся программы

Программы добавляет заказчик в Strapi: в раздел «Сведения → Образование» (`/api/education-sections`, slug `obrazovanie`), поле `content` (markdown), каждая программа начинается с заголовка первого уровня вида `# Программа профессиональной переподготовки «…», объёмом 540 часов`; к разделу прикреплены документы (`documents` → «Рабочая программа», PDF). Программы меняются каждый год, добавляются новые — **главная должна подхватывать их сама, без правки кода**.

Правила разбора (на фронте, запрос к API тот же, что уже используется для раздела):
- Делим `content` по строкам, начинающимся с `# ` (H1). Каждый такой кусок — программа. Текст до первого H1 игнорируется.
- Название — текст в кавычках «…» из заголовка; если кавычек нет — весь заголовок без слова «Программа…».
- Факты ищем в тексте программы простыми правилами; если факт не найден — его плитка не показывается (не выдумывать): часы — число перед «час»; срок — фраза после «Продолжительность обучения … –»; форма — слово перед «форме» («очно-заочной» → «Очно-заочно»); документ — «Диплом»/«Удостоверение», если встречается.
- Описание — первое предложение после заголовка, очищенное от markdown; если до точки встречается двоеточие (за которым идёт список) — обрезать на двоеточии и поставить точку; не длиннее ~220 знаков (обрезка по слову с «…»). Для текущего текста ожидается: «Целью освоения программы «Практическая психология и психокоррекция здоровья» является формирование профессиональных компетенций и навыков в сфере практической психологии, психологии здоровья, здоровьесберегающих технологий и здорового образа жизни.» (с обрезкой по длине). *(Решение основной сессии.)*
- Если ни одного H1 нет или запрос не удался — блок показывает одну ссылку «Программы обучения → Сведения → Образование», ничего не ломается.
- Ссылка «Описание и рабочая программа →» ведёт на `/sveden/obrazovanie#<якорь программы>`; для этого заголовки H1 на странице раздела получают `id` (якоря). Это единственное изменение страницы раздела «Сведения», и оно не меняет ни её структуру, ни адрес.

Разбор — отдельная чистая функция с маленькой самопроверкой (текущий реальный текст раздела → ожидаемые название, описание и 4 факта).

### Остальные страницы — та же система

Структура и адреса не меняются, меняется вид:
- **Сведения** (`/sveden/:slug`): на компьютере слева боковое меню разделов на фоне `tint` (активный — `accent` и полоса слева), справа контент без «коробки в коробке», читаемая ширина строки (~68–75 символов). Документы — список строк: название, описание, справа «Скачать» + «PDF, 140 КБ»; разделение тоном/отступами, не рамками. Телефон — кнопка «Разделы сведений» раскрывает список, как сейчас.
- **Новости** — сетка карточек без рамок/теней: фото 3:2, дата, заголовок, превью. **Новость** — колонка для чтения, крупный заголовок, фото, текст.
- **Расписание / Учебная литература** — списки файлов как документы в «Сведениях».
- **Фотогалерея** — сетка альбомов, обложки с прямыми углами; лайтбокс как сейчас.
- **Контакты** — карточки сотрудников (ФИО, должность, телефон, email), как сейчас по данным, в новой системе.
- **Поиск, 404, «О проекте»** — в новой системе; `/about` не трогаем по составу (решение заказчика отложено).
- **Подвал** — тёмный (`ink`), название «УМЦ «Темпус»» крупно, короткая навигация, контакты, телефон директора, ссылка на «Сведения» — как завершение страницы, а не «ферма ссылок».
- Состояния загрузки/ошибки/пустого списка (`StatusMessage`) — сохранить, оформить в новой системе.

### Версия для слабовидящих

Кнопка «Версия для слабовидящих» в шапке (на телефоне — в меню). Включает панель настроек над шапкой:
- размер текста: обычный / крупный (≈150%) / очень крупный (≈200%);
- цвет: чёрным по белому / белым по чёрному / тёмно-синим по голубому;
- изображения: показывать / скрыть;
- кнопка «Обычная версия».

Реализация: класс/атрибуты на `<html>` + CSS-переменные; выбор хранится в `localStorage` (обёрнут в try/catch), применяется до первой отрисовки (без мигания), без внешних библиотек. В режиме: без анимаций, увеличенный межстрочный, подчёркнутые ссылки, видимый фокус. Обычная версия при этом не меняется. Нормативная основа: в действующих редакциях приказа Рособрнадзора № 1493 нашёлся пункт 25 «б» — возможность навигации, поиска и использования текстовой информации при отключённой графике; прямой формулировки «версия для слабовидящих» в доступных редакциях не найдено. Делаем по решению заказчика и обычной практике (ГОСТ Р 52872-2019). Сайт также должен оставаться пригодным при отключённых картинках (альты, текст не на картинках).

### Движение

Сдержанно: появление блоков при прокрутке (подъём 16–24px + прозрачность, один раз), отклик на наведение/нажатие у кнопок, ссылок и плиток, плавное появление выпадающего меню. Только `transform`/`opacity`. Всё отключается при `prefers-reduced-motion` и в версии для слабовидящих. Контент никогда не остаётся скрытым, если анимация не сработала (сейчас `.reveal` прячет элементы до прокрутки — это заменить).

### Доступность

Видимый фокус (уже есть, сохранить), контраст текста ≥ 4.5:1, альты у изображений, `lang="ru"`, семантика (`header/nav/main/footer`, заголовки по порядку), цели нажатия ≥ 44px на телефоне, «Перейти к содержимому» в начале страницы.

## Что оставлено исполнителю

- Как организовать CSS (файлы, порядок слоёв). Ожидание: старые правила с `!important` и дубли из `App.css` удаляются там, где их заменяют новые; итоговый CSS заметно меньше и без `!important`, кроме обоснованных случаев.
- Конкретные отступы, брейкпоинты (один-два: ~980px и ~640px), микротипографика.
- Формат и размер оптимизированного фото, способ подключения шрифта (файлы в `public/fonts` или npm-пакет с OFL — главное, локально и с лицензией).
- Где ещё повторить мотив «ступеней» (не чаще одного раза на экран).

## Проверка

- `npm run build` без ошибок и предупреждений; `grep -rn "1337" src dist` — пусто.
- Запросы к API не изменились: `git diff` по `fetch(` — только перенос кода, не URL/параметров.
- Все 14 ссылок меню «Сведений» открывают свои разделы.
- Каждая страница на 1440 / 768 / 375 / 320: без горизонтальной прокрутки, заголовки ≤ 2 строк, шапка и подвал на месте.
- Программы на главной: с реальными данными — 1 программа и 4 факта; с подменённым ответом без H1 — запасная ссылка; с двумя H1 — два блока.
- Версия для слабовидящих: все режимы, сохраняется после перезагрузки, работает с клавиатуры.
- Инструменты скилла design-taste-frontend: `lint.mjs` по `src/` — без FAIL; `inspect.mjs` на главной, `/news` и `/sveden/dokumenty` — без FAIL, кроме разрешённых исключений `--allow still-page,empty-screens` (движение намеренно сдержанное по решению заказчика; на коротких страницах честно нет 8 движущихся элементов и полного экрана контента). Короткие страницы (404, поиск, «О проекте», небольшие разделы «Сведений») проверяются скриншотами. Тень у выпадающего меню — допустимое исключение (всплывающий элемент). Символы ✕/☰ в кнопке «Разделы сведений» заменить на SVG-иконки. Скриншоты на трёх ширинах осмотрены. *(Решение основной сессии.)*

## Следующий шаг после редизайна

Отдельный общий субагент проверки уязвимостей (по просьбе заказчика) — проектируется после завершения редизайна.
